What's new in v0.2

Same script tag, same API, same payload. v0.2 makes delivery sturdier, the collector more private, and surveys more capable, and adds signals you can switch on when you need them.

Delivery you can count on

  • Fixed

    A flush now drains the whole buffer, so busy pages no longer leave events behind.

  • New

    Every event and survey answer carries an id, and the collector ignores retried duplicates.

  • Fixed

    No unload handlers: pages stay in the back/forward cache, and a restored page counts as a view.

  • Fixed

    Background tabs stop sending heartbeats, and destroy() removes every listener tinyux added.

A more private collector

  • New

    The database lives in a tinyux-data/ folder that blocks web access.

  • Changed

    The log keeps counts, never IP addresses, and requests are same-origin unless you list other sites.

  • New

    v0.1 databases upgrade in place. --prune deletes old rows and --check flags risky setups.

Surveys that fit your product

  • New

    NPS surveys from 0 to 10, plus a follow-up question that only appears for the answers you choose.

  • Changed

    Modals use the native <dialog>, so keyboard focus stays inside and returns afterwards. Corner prompts never steal focus.

  • New

    Light, dark, or automatic themes, CSS variables for your brand, translatable button labels, and a CSP nonce.

Signals and controls you opt into

  • New

    spa: true records a page view on every client-side route change.

  • New

    frustration: true records rage clicks and dead clicks with coarse coordinates.

  • New

    Consent mode, Global Privacy Control, cookieless storage, and session sampling.

  • Changed

    Anonymous ids rotate after 13 months, and the old mouse sampling option is gone.

new options, all off by default
<script src="/js/tinyux.min.js"
  data-app-id="acme-app"
  data-api-url="/collect.php"
  data-config='{
    "spa": true,
    "frustration": true,
    "consent": "pending",
    "respectGPC": true,
    "storage": "session",
    "ui": {"theme": "auto"}
  }'>
</script>

// later, from your consent banner
tinyux.consent(true)

Upgrading from v0.1

Replace tinyux.js and collect.php. Nothing else is required.

  • tinyux.dbUpgraded in place on the first request. Don't re-run schema.sql on it.
  • $ALLOWED_ORIGINSList your app's origin if the collector runs on another domain.
  • mouseSamplingRemoved. Delete it from your config if you set it.

Still one file: 13.6 KB gzipped with every option included, covered by 50 automated tests. Read the upgrade guide or the full changelog.

The whole loop, from tag to table

tinyux keeps the data path intentionally boring: browser events, optional survey prompts, one collector endpoint, and tables you own.

  1. 01embed

    One static file

    No framework, package manager, extension, or vendor account required.

    app id + endpoint
    auto-init
  2. 02observe

    Behavioral signals

    Page views, clicks, aggregate heatmap points, scroll depth, focus changes, section views, heartbeats, and opt-in rage and dead clicks.

    click / heat / focus
  3. 03ask

    Micro-surveys

    Rating, NPS, yes/no, choices, and optional text prompts with follow-ups and cooldown rules.

    "Why now?"
  4. 04report

    Batched delivery

    sendBeacon and keepalive fetch, local retry for failed sends, and ids so retries never double count.

    events[] + surveys[]
  5. 05own

    Your database

    PHP/SQLite collector stores clients, sessions, events, surveys, and failures in a folder the web can't reach.

    tinyux-data/tinyux.db

Signals small enough to trust

tinyux records metadata about interaction context. It can collect aggregate click/tap heatmap points, but it does not replay a user's screen, record typed content, or ship private product data to a third-party workspace.

page_view

Page views

Initial URL, referrer, viewport, scroll depth, focus time, and client/session IDs. With spa: true, client-side route changes too.

interaction

Interactions

Bind selectors or add attributes to key CTAs, forms, and controls.

section_view

Section views

IntersectionObserver-powered section visibility, with cooldown and once-per-session options.

focus · blur

Focus and blur

Know whether a user left the page during a task or returned to continue.

heatmap_point

Aggregate heatmaps

Optional click/tap density points with coarse coordinates and sanitized element metadata.

identify

User association

Attach your own user, account, plan, or role IDs when your app already knows them.

ui.mode

Corner prompts

Use blocking modal surveys or subtle non-blocking prompts in any corner.

exit_intent

Exit intent

Detect top-edge pointer movement and ask one last contextual question.

heartbeat

Heartbeats

Periodic pulses make abandoned sessions and long-running tasks visible server-side.

input_meta

Input metadata

Optional lengths/types only. Values are never captured by default.

survey_shown · survey_submitted

Survey lifecycle

Shown, closed, skipped, and submitted events tie answers to page context, so you can see who dismissed a prompt.

track()

Custom events

Queue your own event types with any JSON metadata, for checkout steps, feature use, or Web Vitals.

rage_click

Rage clicks

Three or more fast clicks in one spot, recorded once per burst with coarse coordinates.

dead_click

Dead clicks

A click on a button or link that changes nothing on the page within a second.

Triggers

Declare them in HTML, or call ux.showSurvey() from your own code.

  • clickAsk after a specific button or link.
  • section-scrollAsk once a section is 50% visible, once per session.
  • timeAsk after data-tinyux-after-ms, 5000 ms by default.
  • exit-intentAsk when the pointer heads for the top edge.

Placement and guardrails

A blocking center modal by default, built on the native <dialog>, or a non-blocking corner prompt with ui.mode: 'corner' in any of four corners.

  • maxPerSession: 2Global cap on prompts per session.
  • minIntervalMinutes: 5Quiet time between any two prompts.
  • oncePerSessionPer-survey, plus cooldownMinutes and maxPerDay.
  • ui.theme: 'auto'Light, dark, or the visitor's system setting. Restyle with --tinyux-* CSS variables.
  • ui.labelsRename or translate every button and message.

Set up in the next five minutes

Two files, and the collector creates its own tables. Use the AI-agent path if you want a coding assistant to place the script and wire the collector.

One command

Grab the files

Download the client and the collector. The collector creates its SQLite schema on the first request.

terminal
# client library
curl -LO https://tanzir71.github.io/tinyuxjs/tinyux.js

# collector, then check where data will live
curl -LO https://tanzir71.github.io/tinyuxjs/collect.php
php collect.php --check

Put collect.php and tinyux.js where PHP can serve them. The database goes in a protected tinyux-data/ folder; schema.sql is there if you prefer to create it yourself.

Manual

Copy the tag

Already have the file hosted? Drop the tag and add triggers where context matters.

html
<script src="/js/tinyux.js"
  data-app-id="acme-app"
  data-api-url="/collect.php"
  data-config='{"surveys":{"maxPerSession":2}}'>
</script>

See declarative triggers for click, section, time, and exit-intent surveys.

Compliance-friendly by design

tinyux does not make your product compliant by itself. It gives privacy-sensitive teams a smaller, self-hosted telemetry surface for GDPR / UK GDPR, CCPA / CPRA, SOC 2, and internal data-governance workflows.

Data minimization

No replay, screenshots, DOM snapshots, keystroke contents, form values, console logs, or network logs by default. Heatmaps are aggregate click and tap points only.

Processor control

Events, survey answers, identities, and request metadata land on your endpoint and database, so retention, deletion, access, and export stay under your infrastructure controls. --prune enforces retention, and the log never records IP addresses.

Consent-aware setup

Keep tinyux behind your consent gate, pass known user or account IDs explicitly, and leave optional request metadata disabled unless your policy allows it. With consent: 'pending' nothing is stored or sent until your banner calls tinyux.consent(true); Global Privacy Control, cookieless storage, and 13-month id rotation are one setting each.

Never captured by default

  • DOM snapshots
  • Keystroke contents

Why use tinyux instead of a behavior suite?

Hotjar, FullStory, LogRocket, and PostHog are far larger systems. tinyux is for the narrower job: collect useful UX context without buying a platform.

Self-hosted by default

Your events and survey responses land in your own SQLite database. No replay vendor owns the raw trail.

Friction at the source

Small enough to audit

One readable client file and one PHP collector. No black-box recorder and no account setup.

What it deliberately does not do

Honest limits keep tinyux useful. If you need full product analytics, choose a real analytics platform. If you need session replay, choose a replay tool.

No replay theater

No DOM playback, video-style recordings, screenshots, console logs, network capture, or keystroke contents. Heatmaps are aggregate click/tap coordinates only.

No false certainty

Client-side telemetry is directional. Use it to find friction, prompt follow-up, and prioritize fixes, not to claim perfect behavioral truth.

Questions teams ask first

More detail in the implementation guide.

Is this a Hotjar or FullStory replacement?

No. tinyux is for targeted telemetry, contextual feedback, and optional aggregate click/tap heatmaps. It is not a replay, screenshot, or visual behavior suite.

Does it work in SPAs?

Yes. Set spa: true and tinyux records a page_view on every client-side route change. The mutation observer also picks up declarative triggers on new elements.

What happens when the network drops?

Failed payloads are kept in storage with exponential backoff and retried on later flushes or the next page load. Each event has an id, so the collector ignores anything delivered twice.

Do I need a consent banner?

That depends on where you operate and how you configure tinyux. If you need consent, set consent: 'pending': tinyux stores and sends nothing until your banner calls tinyux.consent(true).

How do I upgrade from v0.1?

Replace tinyux.js and collect.php. The collector upgrades your database on its first request. See the upgrade guide.

Can I require an API key?

Yes for normal fetch sends. sendBeacon cannot set custom headers, so strict API-key deployments may disable beacon reliance or validate origin/session instead.

Is text survey input safe?

Text surveys can collect personal data because users type free-form content. Use rating, yes/no, and choice surveys when possible.
